Cómo Pensar TDAs y Resolver Ejercicios de Parcial

Antes de memorizar código, comprende el modelo mental detrás de los Tipos de Datos Abstractos y la metodología estructurada para razonar cualquier problema desde cero.

1. Qué es un TDA (Definición Formal de Examen)

Un Tipo de Dato Abstracto (TDA) es un tipo de dato definido por el programador que agrupa lógicamente:

  • Un conjunto de datos (qué información almacena).
  • Un conjunto de operaciones permitidas sobre esos datos (con sus precondiciones y poscondiciones).

El principio fundamental de un TDA es la separación entre Especificación (Interfaz) e Implementación (Clase):

Especificación (Interfaz .java)

Define el QUÉ hace la estructura (firmas de métodos como Apilar, Tope). Es el contrato público.

Implementación (Clase .java)

Define el CÓMO lo hace internamente (con un vector fijo de 100 lugares o con nodos enlazados dinámicos). Queda encapsulada con private.

Pregunta clásica de parcial: ¿Por qué conviene separar Especificación de Implementación? 1) Intercambiabilidad: Podemos reemplazar una implementación estática (vector) por una dinámica (nodos) sin modificar una sola línea del código cliente (main o métodos externos).
2) Encapsulamiento y Seguridad: Impide que el código externo modifique índices o punteros internos saltándose las reglas e invariantes de la estructura.

2. La Regla de la Caja Negra y la Trampa de Referencias en Java

Al escribir un método externo (como public static void resolver(PilaTDA p)), estás operando afuera de la caja negra:

  • Prohibido: Acceder a atributos internos (p.arr[i], p.inx), usar p.length o crear arreglos nativos / ArrayList.
  • Permitido: Usar exclusivamente las operaciones de la interfaz y otros TDAs auxiliares.
Error Crítico de Java: Asignar referencias no duplica objetos Escribir ColaTDA duplicado = c; NO crea una copia. En Java, las variables de objetos almacenan referencias en memoria: tanto duplicado como c apuntan exactamente al mismo objeto. Si desacolás de duplicado, vacías también a c.

Forma correcta: Instanciar un objeto nuevo (new ColaLD()), llamar a InicializarCola() y transferir los elementos uno por uno mediante un ciclo while.

Frente a un enunciado en blanco, sigue este proceso de razonamiento lógico antes de codificar:

  1. Analiza el Contrato: Qué parámetros entran, qué tipo devuelve y si la consigna exige preservar/restaurar los parámetros originales.
  2. Elige la Estructura Auxiliar según la Propiedad Requerida:

Módulo 01 · Estructura LIFO

Pilas (PilaTDA): Teoría, Estrategias e Implementación

Especificación formal, análisis de las 3 estrategias estáticas con vectores, implementación dinámica mediante nodos y visualización en tiempo real.

1. Especificación Lógica

Una Pila es una estructura lineal ordenada donde los elementos solo se insertan y eliminan por un único extremo denominado tope. Sigue la disciplina LIFO (Last In, First Out): el último elemento en ingresar es el primero en salir.

MétodoDescripciónPrecondición
void InicializarPila()Prepara la estructura vacía.No aplica.
void Apilar(int x)Inserta x en el tope actual.Pila inicializada.
void Desapilar()Elimina el elemento ubicado en el tope.Pila inicializada y no vacía.
int Tope()Devuelve el valor del tope sin eliminarlo.Pila inicializada y no vacía.
boolean PilaVacia()Devuelve true si no contiene elementos.Pila inicializada.

2. ¿Por qué hay tantos archivos? Interfaz vs Implementaciones

Cómo leer los nombres de clases y variables en UADE

En Java se separa el qué hace (la Interfaz PilaTDA) del cómo se guarda por dentro (las Implementaciones). Cuando programas un ejercicio, tu código solo ve PilaTDA, aunque por debajo puede usar cualquiera de estas 4 implementaciones:

PilaTDA (Interfaz)
Es solo el contrato público: define Apilar, Desapilar, Tope, etc. No guarda datos.
TF / TI / TF2 (Estáticas)
TF = Tope al Final (en arr[inx-1])
TI = Tope al Inicio (en arr[0])
TF2 = Tope al Final v2 (usa arr[0] como contador).
LD (Lista Dinámica)
Usa nodos enlazados (primero → sig) sin límite fijo de arreglo.
Variable int inx
Viene de index (índice): cuenta cuántos elementos hay y marca la próxima casilla libre en arr[].

Estática 1 (PilaTF - Tope al Final)

Usa un arreglo int[] arr y una variable int inx que indica la cantidad de elementos y la primera posición libre.

  • Apilar(x): arr[inx] = x; inx++; → O(1)
  • Desapilar(): inx--; → O(1) (El dato permanece fuera del rango válido i >= inx)
  • Tope(): return arr[inx - 1]; → O(1)

Estática 2 (PilaTI - Tope al Inicio)

Mantiene el tope fijo en arr[0], obligando a desplazar todo el vector en cada inserción o eliminación.

  • Apilar(x): Desplaza a la derecha y pone arr[0] = x; → O(n)
  • Desapilar(): Desplaza a la izquierda y inx--; → O(n)
  • Tope(): return arr[0]; → O(1)

Estática 3 (PilaTF2 - Contador en arr[0])

Análoga a PilaTF, pero elimina la variable inx guardando la cantidad de elementos en la celda arr[0]. Los datos se alojan desde arr[1] hasta arr[arr[0]].

Dinámica (PilaLD - Lista Enlazada)

Cada elemento es un Nodo (info, sig). La referencia primero siempre apunta al tope. Se inserta y elimina al inicio en O(1) sin límite de capacidad fija.

PilaTDA (Interfaz): El contrato público oficial de UADE. Solo define métodos (Apilar, Desapilar, Tope, etc.). No contiene arreglos ni código interno.
public interface PilaTDA {
    void InicializarPila(); // pre: no aplica.
    void Apilar(int x);     // pre: pila inicializada.
    void Desapilar();       // pre: pila inicializada y no vacía.
    boolean PilaVacia();    // pre: pila inicializada.
    int Tope();             // pre: pila inicializada y no vacía.
}
public class PilaTF implements PilaTDA {
    int[] arr;
    int inx;

    public void InicializarPila() {
        arr = new int[100];
        inx = 0;
    }
    public void Apilar(int x) { arr[inx] = x; inx++; }
    public void Desapilar() { inx--; }
    public boolean PilaVacia() { return (inx == 0); }
    public int Tope() { return arr[inx - 1]; }
}
public class PilaTI implements PilaTDA {
    int[] arr; int inx;
    public void InicializarPila() { arr = new int[100]; inx = 0; }
    public void Apilar(int x) {
        for (int i = inx - 1; i >= 0; i--) arr[i + 1] = arr[i];
        arr[0] = x; inx++;
    }
    public void Desapilar() {
        for (int i = 0; i < inx; i++) arr[i] = arr[i + 1];
        inx--;
    }
    public boolean PilaVacia() { return (inx == 0); }
    public int Tope() { return arr[0]; }
}
public class PilaTF2 implements PilaTDA {
    int[] arr; // arr[0] almacena la cantidad de elementos
    public void InicializarPila() { arr = new int[100]; arr[0] = 0; }
    public void Apilar(int x) { arr[arr[0] + 1] = x; arr[0]++; }
    public void Desapilar() { arr[0]--; }
    public boolean PilaVacia() { return (arr[0] == 0); }
    public int Tope() { return arr[arr[0]]; }
}
public class PilaLD implements PilaTDA {
    private class Nodo { int info; Nodo sig; }
    private Nodo primero; // El primer nodo representa el tope

    public void InicializarPila() { primero = null; }
    public void Apilar(int x) {
        Nodo nuevo = new Nodo();
        nuevo.info = x;
        nuevo.sig = primero;
        primero = nuevo;
    }
    public void Desapilar() { primero = primero.sig; }
    public boolean PilaVacia() { return (primero == null); }
    public int Tope() { return primero.info; }
}

Misión 01: El Verificador de Capicúa (Palíndromo en PilaTDA)

🎯 1. El Problema & Analogía del Mundo Real

Una secuencia es capicúa o palíndroma cuando se lee exactamente igual en ambos sentidos (por ejemplo, el número 13531 o la secuencia [4, 8, 15, 8, 4]). Los compiladores utilizan pilas para validar simetrías en expresiones matemáticas y etiquetas de lenguajes. Tu objetivo es construir un método cliente que determine si los elementos de una pila forman una secuencia capicúa, sin alterar en absoluto la pila original.

📐 2. Especificación Técnica Rigurosa (Firma Java UADE)

public static boolean esCapicua(PilaTDA p)
  • Parámetro recibido: PilaTDA p (pila inicializada con 0 o más números enteros).
  • Valor devuelto: true si la secuencia de elementos leída del tope a la base es idéntica a la leída de la base al tope; false en caso contrario. Una pila vacía o de 1 solo elemento se considera capicúa por definición.
  • Precondición formal: p debe estar inicializada.
  • Postcondición formal: Al concluir la ejecución, p debe contener exactamente los mismos elementos y en el mismo orden que tenía al ingresar.

⚠️ 3. Reglas de Oro & Trampas Mortales de Parcial (Donde reprueban los alumnos)

Trampa 1: Pérdida de Datos Si desapilas p para comparar los números y no los guardas en pilas auxiliares, la pila queda destruida al finalizar el método y el examen se califica con 0 puntos.
Trampa 2: La Comparación Simultánea Para comparar la pila al derecho y al revés, debes crear copias independientes. Si comparas desapilando dos copias que no restauraste, te quedarás sin datos.
Trampa 3: No usar arreglos internos Como método cliente, solo puedes invocar los métodos oficiales: Apilar, Desapilar, Tope, PilaVacia e InicializarPila. Prohibido intentar acceder a campos internos.

A. Entrada: p = [2, 7, 2] (Tope: 2, Centro: 7, Base: 2).
B. Paso 1: Clonar p en dos pilas: directa (orden idéntico) e invertida (orden reverso volcando directamente).
C. Paso 2: Comparar tope a tope mientras ninguna esté vacía: directa.Tope() == invertida.Tope(). Si en algún momento difieren, no es capicúa.
D. Paso 3: Garantizar que p original se encuentre 100% restaurada antes de devolver el resultado booleano.

Módulo 02 · Estructura FIFO y Prioridades

Colas (ColaTDA) y Colas con Prioridad (ColaPrioridadTDA)

Comprende el modelo de doble referencia (primero y ultimo) en memoria dinámica y el ordenamiento de prioridades.

1. Cola Común (ColaTDA - FIFO)

En una Cola, los elementos ingresan por el final (Acolar) y egresan por el frente (Desacolar), respetando la regla FIFO (First In, First Out).

Estrategias Estáticas (ColaPU vs ColaPI)
  • E1 (ColaPU - Primero al Último): Desacolar es O(1); Acolar desplaza a la derecha (O(n)).
  • E2 (ColaPI - Primero al Inicio): Acolar es O(1); Desacolar desplaza a la izquierda (O(n)).
  • E3 (ColaPU2): Usa arr[0] para guardar la cantidad.
Por qué ColaLD logra O(1) en ambos

Mantiene dos referencias: primero (frente que sale) y ultimo (final donde entran). Esto evita tener que recorrer la lista para encontrar el final al acolar.

ColaTDA (Interfaz): Contrato público de Cola FIFO (First-In, First-Out). Define Acolar, Desacolar, Primero, ColaVacia.
public interface ColaTDA {
    void InicializarCola(); // pre: no aplica.
    void Acolar(int x);     // pre: cola inicializada.
    void Desacolar();       // pre: cola inicializada y no vacía.
    boolean ColaVacia();    // pre: cola inicializada.
    int Primero();          // pre: cola inicializada y no vacía.
}
public class ColaPU implements ColaTDA {
    int[] arr; int inx;
    public void InicializarCola() { arr = new int[100]; inx = 0; }
    public void Acolar(int x) {
        for (int i = inx - 1; i >= 0; i--) arr[i + 1] = arr[i];
        arr[0] = x; inx++;
    }
    public void Desacolar() { inx--; }
    public boolean ColaVacia() { return (inx == 0); }
    public int Primero() { return arr[inx - 1]; }
}
public class ColaPI implements ColaTDA {
    int[] arr; int inx;
    public void InicializarCola() { arr = new int[100]; inx = 0; }
    public void Acolar(int x) { arr[inx] = x; inx++; }
    public void Desacolar() {
        for (int i = 0; i < inx - 1; i++) arr[i] = arr[i + 1];
        inx--;
    }
    public boolean ColaVacia() { return (inx == 0); }
    public int Primero() { return arr[0]; }
}
public class ColaLD implements ColaTDA {
    class Nodo { int info; Nodo sig; }
    Nodo primero; // frente (sale)
    Nodo ultimo;  // final (entra)

    public void InicializarCola() { primero = null; ultimo = null; }
    public void Acolar(int x) {
        Nodo nuevo = new Nodo();
        nuevo.info = x; nuevo.sig = null;
        if (ultimo != null) ultimo.sig = nuevo;
        ultimo = nuevo;
        if (primero == null) primero = ultimo;
    }
    public void Desacolar() {
        primero = primero.sig;
        if (primero == null) ultimo = null;
    }
    public boolean ColaVacia() { return (ultimo == null); }
    public int Primero() { return primero.info; }
}

2. Cola con Prioridad (ColaPrioridadTDA)

Cada dato ingresa acompañado de una prioridad numérica: AcolarPrioridad(int x, int prioridad). El método Primero() y Desacolar() actúan siempre sobre el elemento de mayor prioridad.

  • Estática E1 (ColaPrioridadDA): Dos arreglos paralelos elementos[] y prioridades[] ordenados en forma ascendente. El más prioritario queda en indice - 1.
  • Estática E2 (ColaPrioridadAO): Un arreglo de objetos Elemento (con atributos valor y prioridad).
  • Dinámica (ColaPrioridadLD): Lista enlazada de NodoPrioridad ordenada de mayor a menor prioridad.
ColaPrioridadTDA (Interfaz): Contrato público de Cola con Prioridad. Quien tiene mayor valor numérico de prioridad sale primero.
public interface ColaPrioridadTDA {
    void InicializarCola();
    void AcolarPrioridad(int x, int prioridad);
    void Desacolar();       // pre: inicializada y no vacía
    boolean ColaVacia();
    int Primero();          // pre: inicializada y no vacía
    int Prioridad();        // pre: inicializada y no vacía
}
public class ColaPrioridadDA implements ColaPrioridadTDA {
    int[] elementos; int[] prioridades; int indice;
    public void InicializarCola() {
        elementos = new int[100]; prioridades = new int[100]; indice = 0;
    }
    public void AcolarPrioridad(int x, int prioridad) {
        int j = indice;
        while (j > 0 && prioridades[j - 1] > prioridad) {
            elementos[j] = elementos[j - 1];
            prioridades[j] = prioridades[j - 1];
            j--;
        }
        elementos[j] = x; prioridades[j] = prioridad; indice++;
    }
    public void Desacolar() { indice--; }
    public boolean ColaVacia() { return (indice == 0); }
    public int Primero() { return elementos[indice - 1]; }
    public int Prioridad() { return prioridades[indice - 1]; }
}
public class ColaPrioridadLD implements ColaPrioridadTDA {
    class NodoPrioridad { int info; int prioridad; NodoPrioridad sig; }
    NodoPrioridad primero;

    public void InicializarCola() { primero = null; }
    public void AcolarPrioridad(int x, int prioridad) {
        NodoPrioridad nuevo = new NodoPrioridad();
        nuevo.info = x; nuevo.prioridad = prioridad;
        if (primero == null || primero.prioridad < prioridad) {
            nuevo.sig = primero;
            primero = nuevo;
        } else {
            NodoPrioridad aux = primero;
            while (aux.sig != null && aux.sig.prioridad >= prioridad) aux = aux.sig;
            nuevo.sig = aux.sig;
            aux.sig = nuevo;
        }
    }
    public void Desacolar() { primero = primero.sig; }
    public boolean ColaVacia() { return (primero == null); }
    public int Primero() { return primero.info; }
    public int Prioridad() { return primero.prioridad; }
}

Módulo 03 · Punteros y Memoria Dinámica

Nodos y Listas Enlazadas

Entiende cómo funcionan los punteros, el nodo viajero aux, por qué existen dos formas de recorrer una lista y cómo circunvalar para eliminar nodos.

1. Anatomía del Nodo y el Nodo Viajero aux

En una lista enlazada los datos no ocupan posiciones contiguas. Cada elemento es un objeto Nodo con un dato (info) y una referencia al siguiente nodo (sig). El final se marca con null.

Regla Fundamental: No desplaces la referencia principal (origen) Si modificas el puntero principal haciendo u = u.sig; mientras recorres, pierdes los nodos iniciales para siempre. Siempre usa una copia viajera: Nodo aux = u;.

2. Las Dos Estrategias de Recorrido

Estrategia A: Mirar al nodo actual

while (aux != null && aux.info != num)

aux se detiene posado sobre el nodo buscado (o en null).
Usos: Buscar, leer, mostrar o actualizar un valor.

Estrategia B: Mirar al nodo siguiente

while (aux.sig != null && aux.sig.info != num)

aux se detiene un paso antes del objetivo para poder modificar la flecha aux.sig al insertar o circunvalar (aux.sig = aux.sig.sig). Requiere tratar al primer nodo como caso especial.

3. Operaciones Básicas en Listas Enlazadas

public static Nodo AgregarInicio(Nodo u, int num) {
    Nodo nuevo = new Nodo();
    nuevo.info = num;
    nuevo.sig = u;
    return nuevo;
}
public static Nodo AgregarFinal(Nodo u, int num) {
    Nodo nuevo = new Nodo();
    nuevo.info = num; nuevo.sig = null;
    if (u == null) {
        u = nuevo;
    } else {
        Nodo aux = u;
        while (aux.sig != null) aux = aux.sig;
        aux.sig = nuevo;
    }
    return u;
}
public static Nodo AgregarOrdenado(Nodo u, int num) {
    Nodo nuevo = new Nodo();
    nuevo.info = num; nuevo.sig = null;
    if (u == null) {
        u = nuevo;
    } else if (u.info > num) {
        nuevo.sig = u; u = nuevo;
    } else {
        Nodo aux = u;
        while (aux.sig != null && aux.sig.info < num) aux = aux.sig;
        nuevo.sig = aux.sig; // Primero apunta hacia adelante
        aux.sig = nuevo;     // Luego el anterior apunta al nuevo
    }
    return u;
}
public static Nodo Eliminar(Nodo u, int num) {
    if (u != null) {
        if (u.info == num) { // Caso especial: eliminar el origen
            u = u.sig;
        } else {
            Nodo aux = u;
            while (aux.sig != null && aux.sig.info != num) aux = aux.sig;
            if (aux.sig != null) aux.sig = aux.sig.sig; // Circunvalar
        }
    }
    return u;
}

Estructuras clave para filtrar duplicados, calcular frecuencias y agrupar colecciones por clave en parciales.

1. Conjuntos (ConjuntoTDA)

Colección de enteros sin orden posicional y sin repeticiones.

  • Operaciones: InicializarConjunto(), Agregar(x) (solo si !Pertenece(x)), Sacar(x), Elegir() (arbitrario), Pertenece(x), ConjuntoVacio().
  • Optimización en ConjuntoA: Al eliminar el elemento en a[i], no desplaza el vector; simplemente copia el último en su lugar: a[i] = a[cant - 1]; cant--;.

2. Diccionario Simple y Diccionario Múltiple

Diccionario Simple

Relación Clave única → Único Valor. Si se agrega una clave ya existente, sobrescribe el valor. Se recorre pidiendo el conjunto de claves vía d.Claves().

Diccionario Múltiple

Relación Clave única → Conjunto de Valores. Al ejecutar EliminarValor(clave, valor), si el conjunto de valores queda vacío, debe eliminarse la clave entera.

public class ConjuntoA implements ConjuntoTDA {
    private int[] a; private int cant;
    public void InicializarConjunto() { a = new int[100]; cant = 0; }
    public void Agregar(int x) { if (!Pertenece(x)) { a[cant] = x; cant++; } }
    public boolean Pertenece(int x) {
        int i = 0;
        while (i < cant && a[i] != x) i++;
        return (i < cant);
    }
    public void Sacar(int x) {
        int i = 0;
        while (i < cant && a[i] != x) i++;
        if (i < cant) { a[i] = a[cant - 1]; cant--; }
    }
    public int Elegir() { return a[cant - 1]; }
    public boolean ConjuntoVacio() { return (cant == 0); }
}
public class DiccionarioSimpleA implements DiccionarioSimpleTDA {
    class Elemento { int clave; int valor; }
    private Elemento[] elementos; private int cant;
    private int Clave2Ind(int clave) {
        int i = cant - 1;
        while (i >= 0 && elementos[i].clave != clave) i--;
        return i;
    }
    public void Agregar(int clave, int valor) {
        int pos = Clave2Ind(clave);
        if (pos == -1) {
            pos = cant; elementos[pos] = new Elemento();
            elementos[pos].clave = clave; cant++;
        }
        elementos[pos].valor = valor;
    }
    public int Recuperar(int clave) { return elementos[Clave2Ind(clave)].valor; }
    public void Eliminar(int clave) {
        int pos = Clave2Ind(clave);
        if (pos != -1) { elementos[pos] = elementos[cant - 1]; cant--; }
    }
}

Módulo 05 · Estructuras Jerárquicas (2do Parcial)

Árboles Binarios, Tipos, ABBTDA, AVL y Árboles B

Domina la terminología formal, la clasificación de árboles binarios, la recursividad en ABB, los 3 casos de eliminación y por qué AVL y Árboles B garantizan eficiencia logarítmica.

1. Anatomía de un Árbol (Conceptos Clave)

Raíz, Hijos y Hojas

  • Raíz: único nodo sin padre (punto de entrada).
  • Padre / Hijo / Hermanos: relación directa por arista dirigida; nodos con mismo padre son hermanos.
  • Hoja (Nodo Terminal): nodo sin hijos (grado 0).
  • Nodo Interior: nodo que tiene al menos un hijo.

Grado, Nivel y Altura

  • Grado de un nodo: cantidad de hijos que posee (en binario, máximo 2).
  • Nivel / Profundidad: distancia desde la raíz (raíz en nivel 1 o profundidad 0 según convención).
  • Altura del árbol (h): profundidad del nodo hoja más lejano (determina el costo de búsqueda).

Definición Recursiva UADE

Un árbol binario es vacío, o bien una tupla formada por un elemento (Raiz()) y dos subárboles binarios disjuntos (HijoIzq() y HijoDer()).

Esta definición recursiva explica por qué casi todos los métodos sobre ABBTDA tienen 20% del largo usando recursión.

2. Los 4 Tipos Clásicos de Árboles Binarios (Pregunta Fija de Examen)

A. Árbol Binario Estricto (Propio)

Todo nodo tiene exactamente 0 hijos (hoja) o 2 hijos. Ningún nodo posee un solo hijo.

B. Árbol Binario Lleno (Perfecto)

Todos los nodos interiores tienen 2 hijos y todas las hojas están al mismo nivel. Con k niveles tiene exactamente 2k - 1 nodos.

C. Árbol Binario Completo

Todos los niveles están llenos excepto posiblemente el último, donde las hojas se acomodan continuamente de izquierda a derecha (sin huecos).

D. Árbol Degenerado (Patológico)

Cada padre tiene a lo sumo 1 hijo. Ocurre al insertar datos ya ordenados en un ABB (ej. 10, 20, 30, 40). Se comporta como lista enlazada con costo O(n).

3. Árbol Binario de Búsqueda (ABBTDA), Recorridos y Eliminación

Propiedad Invariante del ABB: Para todo nodo, todos los valores en su HijoIzq() son estrictamente menores a Raiz(), y todos los de su HijoDer() son estrictamente mayores.

Preorden (R → I → D)

Visita raíz primero. Útil para clonar o reconstruir la misma topología de árbol.

Inorden (I → R → D)

En un ABB entrega los valores ordenados de menor a mayor. Clave para comparar dos ABB.

Postorden (I → D → R)

Procesa hijos antes que la raíz. Ideal para liberar nodos o calcular alturas.

Los 3 Casos de EliminarElem(x) en ABB

  1. Caso 1 — Nodo Hoja: No tiene hijos. Se reemplaza por null directamente.
  2. Caso 2 — Nodo con 1 Hijo: Su único subárbol (izquierdo o derecho) sube a ocupar su lugar.
  3. Caso 3 — Nodo con 2 Hijos: Se busca el mayor elemento del subárbol izquierdo (mayor(HijoIzq), bajando siempre a derecha) o el menor del derecho, se copia ese valor en el nodo a borrar, y se elimina recursivamente dicho reemplazante de su subárbol original.
public interface ABBTDA {
    int Raiz();              // árbol inicializado y no vacío
    ABBTDA HijoIzq();        // subárbol izquierdo (pre: no vacío)
    ABBTDA HijoDer();        // subárbol derecho (pre: no vacío)
    boolean ArbolVacio();    // true si raiz == null
    void InicializarArbol();
    void AgregarElem(int x);
    void EliminarElem(int x);
}
class NodoABB { int info; ABBTDA hijoIzq, hijoDer; }
public class ABB implements ABBTDA {
    NodoABB raiz;
    public void InicializarArbol() { raiz = null; }
    public boolean ArbolVacio() { return raiz == null; }
    public int Raiz() { return raiz.info; }
    public ABBTDA HijoIzq() { return raiz.hijoIzq; }
    public ABBTDA HijoDer() { return raiz.hijoDer; }
    public void AgregarElem(int x) {
        if (raiz == null) {
            raiz = new NodoABB(); raiz.info = x;
            raiz.hijoIzq = new ABB(); raiz.hijoIzq.InicializarArbol();
            raiz.hijoDer = new ABB(); raiz.hijoDer.InicializarArbol();
        } else if (x < raiz.info) raiz.hijoIzq.AgregarElem(x);
        else if (x > raiz.info) raiz.hijoDer.AgregarElem(x);
    }
}
public void inOrden(ABBTDA a) {
    if (!a.ArbolVacio()) {
        inOrden(a.HijoIzq());
        System.out.print(a.Raiz() + " "); // en ABB salen ordenados!
        inOrden(a.HijoDer());
    }
}
public void preOrden(ABBTDA a) {
    if (!a.ArbolVacio()) { System.out.print(a.Raiz()+" "); preOrden(a.HijoIzq()); preOrden(a.HijoDer()); }
}

    if (!a.ArbolVacio()) { postOrden(a.HijoIzq()); postOrden(a.HijoDer()); System.out.print(a.Raiz()+" "); }
}

5. Árboles Balanceados AVL y Árboles B

Árbol AVL (Adelson-Velskii y Landis)

Es un ABB auto-balanceado donde para todo nodo se cumple que el Factor de Equilibrio FE = h(izq) - h(der) vale -1, 0 o +1. Esto garantiza altura O(log n) incluso insertando datos ordenados.

  • Rotación Simple Izq / Der (LL / RR): cuando el desbalance (|FE| = 2) y el hijo pesado tienen el mismo signo.
  • Rotación Doble (LR / RL): cuando el padre tiene signo contrario al hijo (zig-zag); requiere rotar primero al hijo y luego al padre.

Árbol B de Orden m (Multicamino)

Generalización del árbol de búsqueda diseñada para bases de datos y acceso a disco, minimizando la cantidad de lecturas de bloque:

  • Cada nodo contiene hasta m - 1 claves ordenadas y hasta m subárboles hijos.
  • Todas las hojas están al mismo nivel (balanceado perfecto por construcción).
  • Cuando un nodo excede m - 1 claves ocurre un split (división) promocionando la clave media hacia el padre.

Grafos (GrafoTDA): Matriz vs Lista y Recorridos BFS / DFS

Entiende la representación mediante Matriz de Adyacencia y Lista de Adyacencia, las propiedades de vértices y los recorridos sistemáticos usando ColaTDA y PilaTDA.

1. Terminología Esencial de Grafos

Componentes y Dirección

  • Grafo G = (V, E): conjunto de Vértices V y Aristas E.
  • Dirigido (Digrafo): arista (u → v) tiene origen y destino; en UADE GrafoTDA siempre es dirigido y ponderado.
  • Ponderado: cada arista guarda un peso numérico (PesoArista(u, v)).

Grados y Vértices Especiales

  • Grado de Salida: cuántas aristas salen de v.
  • Grado de Entrada: cuántas aristas llegan a v.
  • Vértice Aislado: nodo sin aristas entrantes ni salientes (grado total = 0).

  • Ciclo: camino no vacío que comienza y termina en el mismo vértice.
  • DAG: Grafo Acíclico Dirigido (sin ciclos, ej. correlatividades de materias).
  • Conexo / Fuertemente Conexo: existe camino entre cualquier par de vértices.

    /**
     * Determina si existe un camino desde 'origen' hasta 'destino'
     * cuya longitud en cantidad de aristas sea <= maxSaltos.
     * 
     * Costo temporal esperado: O(V²) con Matriz de Adyacencia
     * Costo espacial auxiliar: O(V) para colas y conjunto de visitados
     */
    public static boolean existeConexion(GrafoTDA g, int origen, int destino, int maxSaltos) {
        if (origen == destino) return true;

        // Cola para los vértices a explorar
        ColaTDA colaV = new ColaLD();
        colaV.InicializarCola();
        
        // Cola sincronizada para registrar la distancia en saltos
        ColaTDA colaD = new ColaLD();
        colaD.InicializarCola();

        // Conjunto de vértices ya visitados para evitar ciclos infinitos
        ConjuntoTDA visitados = new ConjuntoLD();
        visitados.InicializarConjunto();

        colaV.Acolar(origen);
        colaD.Acolar(0);
        visitados.Agregar(origen);

        while (!colaV.ColaVacia()) {
            int actual = colaV.Primero();
            colaV.Desacolar();
            int dist = colaD.Primero();
            colaD.Desacolar();

            if (dist < maxSaltos) {
                // Buscamos todos los adyacentes de 'actual' en el grafo
                ConjuntoTDA verts = g.Vertices();
                while (!verts.ConjuntoVacio()) {
                    int cand = verts.Elegir();
                    verts.Sacar(cand);

                    if (g.ExisteArista(actual, cand)) {
                        if (cand == destino) {
                            return true; // Encontrado dentro de la cota de saltos
                        }
                        if (!visitados.Pertenece(cand)) {
                            visitados.Agregar(cand);
                            colaV.Acolar(cand);
                            colaD.Acolar(dist + 1);
                        }
                    }
                }
            }
        }

        return false;
    }
